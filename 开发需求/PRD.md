# 本地数学公式识别工具 PRD

版本 v0.1 · 2026 年 11 月 23 日 · 待用户审阅

本产品帮助本科生、研究生和数学爱好者，将论文截图、公式图片和鼠标手写公式转换为可编辑的 LaTeX，在本机完成校对与保存，再复制到 WPS 中使用。第一版交付 Windows 桌面应用，围绕单个数学公式完成输入、识别、纠错、复制和再次使用的全过程。

本文中的“已确认”来自需求访谈。“建议默认值”由产品与架构整理过程补充，供本次审阅确认。“待实测”表示需要在目标电脑和实际样例上验证。

## 已确认的使用流程

### 截图与图片输入

用户通过软件截图或上传一个公式图片，获取对应 LaTeX。输出提取公式主体，清除外围公式编号和解释文字，保留公式内部的文字标签、函数名和符号关系。用户通过原图对照与公式预览检查结果，编辑源码完成修正，随后复制到 WPS 使用。

### 鼠标手写输入

用户在软件提供的简易画板内书写数学公式，完成后提交识别。识别结果进入同一套源码编辑、公式预览与复制流程。

第一版手写识别目标包括数字、常见拉丁字母、基本运算、等号与不等号、上下标、分式、平方根及其简单组合。验收样例至少覆盖下列结构，并使用真实鼠标笔迹制作输入。

| 结构 | 目标公式源码示例 |
| --- | --- |
| 基本运算 | `a+b=c` |
| 关系符号 | `x\geq 0` |
| 上标 | `x^2+y^2=r^2` |
| 下标 | `a_n` |
| 分式 | `\frac{x+1}{x-1}` |
| 根式与简单组合 | `\sqrt{x^2+1}` |

画板交互建议参考用户提供的界面，保留画笔、橡皮擦、撤销、清空与提交识别。笔迹保留至用户主动清空或开始新的输入，识别失败后可继续修改并重试。

### 再次使用

用户打开本地历史记录，查看原图、识别得到的 LaTeX 和最新修改结果，继续编辑或再次复制。历史内容在退出应用后仍可读取。

## 功能需求与验证方式

以下优先级均属于当前版本。基础流程先验证，随后完成手写、历史与安装交付。

| 编号 | 功能 | 行为要求 | 验证方式 |
| --- | --- | --- | --- |
| F01 | 软件截图 | 提供截图入口，允许选择单个公式区域 | 从论文阅读窗口截取公式，进入识别流程，保持公式内容完整 |
| F02 | 图片导入 | 导入包含单个公式的图片并显示原图 | 导入目标图片后能识别，并可对照结果。不合法输入显示原因 |
| F03 | 鼠标画板 | 支持鼠标书写和笔迹修正，提交后转换为 LaTeX | 用实际鼠标完成六类已确认手写样例的输入、修正和识别 |
| F04 | 本地识别 | 在目标设备加载识别模型，处理当前公式 | 完成初始化后断网测试，取得源码和预览结果 |
| F05 | 公式主体提取 | 清除外围编号和解释文字，保留公式内部内容 | 对同一公式的干净截图和带编号、说明文字截图分别测试 |
| F06 | 源码与预览 | 显示原图、可编辑 LaTeX 和渲染结果，编辑后更新预览 | 修改下标、分子或根号内容，预览与当前源码一致 |
| F07 | 纠错与撤销 | 提示可检测的语法或渲染问题，支持撤销编辑 | 制造括号缺失等错误，查看提示，修正或撤销后恢复可用状态 |
| F08 | 复制到 WPS | 复制当前编辑版本的 LaTeX，反馈复制结果 | 在用户实际 WPS 版本中粘贴、显示、修改并保存公式 |
| F09 | 本地历史 | 保存原图、识别结果和最新修改，支持重新打开 | 退出并重启软件，打开记录，内容与上次保存状态一致 |
| F10 | 首次运行 | 安装、环境检查、模型下载、加载验证 | 在干净用户环境复现首次准备流程，完成后离线重启使用 |

### 输入与任务规则的建议默认值

- 文件入口先提供 PNG、JPG、JPEG。新增格式依据实际需求和解码验证决定。
- 截图采用鼠标框选，支持取消。识别前允许调整公式区域，外围文字混入时可重新框选。
- 每次提交对应一个公式任务，同一时刻执行一个识别任务。识别期间显示处理中状态，重复点击保持同一任务。
- 提交时固定本次输入。取消后产生的迟到结果按任务标识丢弃，当前编辑内容由用户正在处理的任务决定。
- 空白画板或空白选区显示重新输入提示。图片损坏、无法解码、超出资源限制时说明处理方式。
- 图片尺寸、文件大小和输出长度上限由显存测试确定，随模型版本记录，并在处理前检查。
- 数学内容保留以原图为依据。对外围内容归属不明确的区域，提供重新框选与人工校对入口。

### 编辑与复制规则

公式渲染用于检查排版，原图对照用于核对符号与数学结构。界面状态使用“识别完成”“渲染失败”等与实际处理结果对应的文字。

建议默认复制公式主体 LaTeX 源码，保留公式需要的命令与环境。WPS 的实际粘贴入口、所需分隔符和支持语法在兼容性验证中确定。保留原始识别版本与用户当前编辑版本，便于恢复和追溯。

用户编辑出暂时无法渲染的源码时，保留当前输入并显示提示。撤销恢复之前的编辑内容。复制操作以当前显示的源码为准，渲染异常状态持续可见。

### 历史记录规则的建议默认值

每条记录包含创建时间、输入方式、原始图片、识别源码、最新编辑源码和识别模型版本。截图与上传文件保存副本，手写输入保存提交时的画布图像。

识别成功后自动建立记录，用户编辑后自动保存最新状态，并在离开编辑内容或正常退出前完成写入。写入失败时保留内存中的修改并提示重试。单条记录可由用户确认删除。撤销记录默认服务于当前编辑会话，跨会话继续编辑使用最近一次已保存的内容。

## 代表性公式与判定标准

用户提供的复杂印刷公式包含求和、连乘、上下限、希腊字母、条件概率和嵌套下标。其预期源码可参考以下人工转录，验收时结合原始截图核对。

```latex
p_{\text{RAG-Sequence}}(y\mid x)
\approx
\sum_{z\in\operatorname{top-k}(p(\cdot\mid x))}
p_{\eta}(z\mid x)\,p_{\theta}(y\mid x,z)
=
\sum_{z\in\operatorname{top-k}(p(\cdot\mid x))}
p_{\eta}(z\mid x)
\prod_i^N p_{\theta}(y_i\mid x,z,y_{1:i-1})
```

重点检查 `RAG-Sequence`、`top-k`、条件概率竖线、`\eta` 与 `\theta`、求和下标、`y_{1:i-1}` 以及 `\prod_i^N`。原图连乘下标为 `i`，识别结果应忠实保留。

用户提供的两张参考图已随本文保存在本地。画板界面图提供交互参考，手写识别验收另行收集纯笔迹样例。

## 验收方案

### 印刷公式质量

已确认目标为清晰印刷公式至少 90% 可直接使用。建议正式验收使用事先固定的至少 30 张图片，覆盖简单公式、复杂公式以及用户给出的代表性结构。验收集的组成在模型调试前确定，开发调试样例与最终验收样例分别留存。

每个样例检查识别完成、源码可渲染、数学符号与结构一致、目标 WPS 中可正常使用。公式可使用多种等价 LaTeX 写法，判定以原图内容与数学结构为准。识别正确率在人工编辑前统计，人工修正结果另行记录。

外围编号与解释文字清除使用独立样例测试，重点核对公式内部的函数名、文字下标和数字边界。模糊、截断、空白图片用于异常处理验证，测试报告记录各组的输入条件。

### 鼠标手写质量

已确认支持基础公式及简单组合。建议至少制作 20 张实际鼠标书写样例，覆盖已确认结构，并记录字母、数字和上下标的混淆情况。

手写首识正确率尚待用户确认。草稿建议目标为至少 80%，并要求失败样例能够经过已约定的源码纠错流程完成使用。该数值属于建议默认值，需要与本地验证结果一同审阅。

### 性能与资源

体验期望为提交一张公式到获得源码及预览约 5 秒。计时覆盖图像处理、推理、结果整理和首次预览。

验证报告分别记录应用冷启动、首次加载模型、模型就绪后的识别耗时，以及识别任务的中位数和第 95 百分位耗时。印刷与手写分别报告。约 5 秒目标的最终适用范围和统计口径根据实测确认，冷启动及下载时间单独展示。

测试记录实际显卡型号、显存、内存、Windows 版本、驱动、推理环境、模型版本与推理参数。在目标设备上测量峰值显存和连续识别稳定性。建议执行 30 次连续识别，验证任务恢复、内存释放、界面响应和结果对应关系。

### WPS 与离线验证

记录用户实际安装的 WPS 版本及公式输入步骤。用户已验证 LaTeX 使用流程，工程验收仍需对生成结果进行复现，覆盖求和、连乘、上下标、分式、根式和内部文字标签。

完成模型准备后断网重启，依次测试截图、导入、手写、识别、渲染、历史读取和复制。公式渲染资源、字体和运行组件随本地交付准备。用户内容的处理、日志和存储路径纳入本地行为核查。

## 异常与恢复

以下处理方式属于建议默认值。

| 场景 | 用户可见行为与恢复路径 |
| --- | --- |
| 首次下载中断 | 保留下载状态，说明原因并提供重试。完整性检查通过后使用模型 |
| 模型文件缺失或损坏 | 明确说明需重新下载或修复，进入准备流程 |
| 显卡或驱动环境不满足 | 展示检测结果与所需环境，提供可执行的安装或修复说明 |
| 显存不足 | 保留输入，说明资源不足，允许释放资源后重试 |
| 空白、损坏或无法处理的图片 | 提示重新截图、裁剪或选择文件，保留可用的输入内容 |
| 识别失败或超时 | 保留当前输入，提供重试和取消。超时阈值由实测确定 |
| 源码无法渲染 | 显示当前源码与错误提示，继续允许编辑和撤销 |
| 用户取消识别 | 返回可编辑输入状态，当前内容保持可恢复 |
| 剪贴板写入失败 | 保留源码，提示重试复制或选择源码进行手动复制 |
| 本地存储空间不足 | 明确提示保存失败，保留当前结果并提供重试 |
| 程序重启后打开历史 | 读取最后一次成功写入的记录，异常记录提供可理解的提示 |

## 技术方向与待验证项

用户已选择优先采用专用公式识别路线，最终模型由实际测试决定。桌面界面承载输入、编辑与历史管理，识别模块在本机处理图像并输出 LaTeX，渲染模块显示公式，剪贴板完成与 WPS 的连接。

评估过的两条路线如下。

| 路线 | 采用依据与取舍 | 当前结论 |
| --- | --- | --- |
| 专用公式识别模型 | 直接面向公式图片转 LaTeX，便于围绕印刷与手写样例组织验证。需评估目标 Windows 环境及显卡兼容性 | 用户同意优先采用，UniMERNet 可作为候选 |
| 本地文档视觉模型 | 具备公式识别任务接口，可根据输入样例评估其生成效果、参数配置与部署成本 | 保留为候选技术路线，评估结果决定采用情况 |

UniMERNet 官方项目提供本地推理代码及不同规模模型，并以印刷、截图和手写表达式进行评估。PaddleOCR-VL 的官方模型说明提供公式识别任务接口。公开模型的测试结果仅用于筛选候选，产品质量和速度采用本项目自己的样例与设备验收。[UniMERNet 官方项目](https://github.com/opendatalab/UniMERNet) · [PaddleOCR-VL 官方模型说明](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.5)

最终模型、Windows 界面框架、本地存储实现、图片预处理与渲染库由实现阶段根据验证结果选择。选定版本后记录代码与模型权重来源、许可证、下载位置和校验信息。

首轮技术验证需要回答以下问题。

1. 模型和运行环境能否在实际 5060 8GB Windows 电脑上稳定加载与执行。
2. 用户提供的复杂印刷公式和鼠标手写样例，首识结果能达到什么质量。
3. 峰值显存、加载耗时和识别耗时是否满足产品目标。
4. 外围文字清除能否保留公式内部的文本与符号。
5. 结果在用户实际 WPS 中粘贴、显示和修改的兼容范围。
6. 模型、依赖与安装包的体积，以及首次安装复现过程。

验证结果用于锁定实现方案和验收条件。需要调整已确认的质量目标或功能范围时，与用户重新确认。
