## 1. 产品背景、目标与使用条件

### 1.1 产品定位

本产品帮助本科生、研究生和数学爱好者，将论文截图、公式图片和鼠标手写公式转换为可编辑的 LaTeX，在本机完成校对、预览、保存，并复制到 WPS 中使用。

第一版围绕单个数学公式完成输入、识别、纠错、复制和再次使用，不扩展为通用文档 OCR 或论文解析工具。

### 1.2 已确认条件

| 项目 | 内容 |
| --- | --- |
| 主要用户 | 本科生、研究生、数学爱好者 |
| 主要用途 | 阅读、学习和论文写作时复用公式，减少手工输入 LaTeX 的时间 |
| 首版平台 | 配备独立显卡的 Windows 电脑 |
| 必测设备 | 用户指定的 5060、8GB 显存电脑 |
| 数据处理 | 用户图片、鼠标笔迹、公式源码和历史记录在本机处理、保存 |
| 联网条件 | 首次准备阶段允许经用户确认后联网下载模型；准备完成后离线使用 |
| 目标外部软件 | 用户实际安装的 WPS 文字和 WPS 演示 |
| 团队条件 | 1～2 人，熟练使用 Agent 工具 |
| 印刷质量目标 | 清晰印刷公式验收集的端到端直接可用率至少 90% |
| 速度体验目标 | 单张公式约 5 秒获得源码和预览，最终统计口径待实测确认 |

注：印刷质量目标与速度体验目标的统计口径为拟定规则，分别按 10.2 与 10.6 执行并在 G1 冻结，不视为已验收承诺。

### 1.3 产品价值验证

除识别正确率外，验收报告补充记录：

- 代表性公式从输入到 WPS 可用的端到端耗时。
- 首识失败后的修正耗时和编辑次数。
- 相同样例完全手工录入 LaTeX 的参考耗时。

效率数据用于说明产品价值，首版不单独设置效率发布门槛。

## 2. 首版范围与公式边界

### 2.1 首版包含

- 软件截图并框选公式区域。
- 导入包含单个公式的 PNG、JPG、JPEG 图片。
- 鼠标画板书写、修正并提交识别。
- 本地模型推理并输出 LaTeX。
- 原图、可编辑源码和公式预览对照。
- 可检测的语法或渲染错误提示、编辑撤销。
- 复制当前源码，按验证后的步骤在 WPS 中使用。
- 本地历史查看、继续编辑、再次复制和单条删除。
- Windows 安装、环境检查、模型下载、加载验证和离线运行。

### 2.2 明确不在首版范围

- 图表识别、论文表格识别和整篇论文解析。
- 一张图片中多个相互独立公式的自动拆分。
- 公式 OCR 结果语义计算、化简或数学正确性证明。
- 跨设备同步、账号体系、云端历史。
- 手写板专用压感、触控笔压感能力。
- 跨会话撤销编辑。
- 自动清理历史记录。

以下公式结构不纳入首版验收承诺：矩阵、分段函数、复杂对齐环境、多列公式混排。模型可能输出相关结果，但不得据此宣称首版已支持。

### 2.3 “单个公式”的定义

首版允许以下输入：

- 单行数学公式。
- 在数学语义上连续、由约等号或等号等关系连接的多行推导，例如本文代表性公式。
- 公式周围带独立编号或解释文字，但用户框选区域能够明确区分公式主体与外围内容。

多行公式不保证自动转换为特定 aligned、align 环境；验收以数学符号、结构和关系是否与原图一致为准。

框选或导入区域包含多个相互独立公式时（拟定规则，G0 确认）：

- 首版不自动拆分，按用户提交区域整体识别。
- 输出明显包含多个相互独立的公式主体时，提示用户结果可能不符合预期，建议重新框选单个公式区域。
- 用户选择继续使用的结果按原样保留，不静默丢弃。

### 2.4 手写范围

手写验收覆盖：

- 数字、常见拉丁字母。
- 基本运算、等号和不等号。
- 上下标。
- 分式、平方根及以上结构的简单组合。

基准样例：

| 结构 | 示例 |
| --- | --- |
| 基本运算 | `a+b=c` |
| 关系符号 | `x\geq 0` |
| 上标 | `x^2+y^2=r^2` |
| 下标 | `a_n` |
| 分式 | `\frac{x+1}{x-1}` |
| 根式与简单组合 | `\sqrt{x^2+1}` |

“简单组合”指上述结构之间有限组合；首版手写验收不包含矩阵、分段函数、多层复杂嵌套及长篇连笔推导。具体嵌套样例由手写验收集清单冻结。

## 3. 核心使用流程

### 3.1 截图或图片识别

1. 用户选择截图或图片导入。
2. 软件显示并固定本次输入。
3. 用户确认识别区域并提交。
4. 软件执行本地识别，显示处理中状态。
5. 识别成功后展示原图、原始识别源码、可编辑当前源码和预览。
6. 用户对照原图检查并修正。
7. 用户复制当前源码，按说明在 WPS 中粘贴、显示、修改并保存。
8. 识别成功后建立历史记录，后续编辑自动保存。

### 3.2 鼠标手写识别

1. 用户在画板中书写。
2. 使用画笔、橡皮擦、撤销或清空进行修正。
3. 提交识别后固定当前画布图像。
4. 识别结果进入统一源码编辑、预览和复制流程。
5. 识别失败时保留笔迹，用户可继续修改并重试。

笔迹保留至用户主动清空、开始新的输入或重新截图/导入图片；切换前如存在未保存结果，应按历史保存规则处理。

### 3.3 历史再次使用

用户可查看历史记录的原图、输入方式、原始识别源码、最新编辑源码、模型版本和时间信息，并继续编辑或复制。

重启后读取最后一次成功写入的状态；损坏的单条记录不得阻塞其他记录加载。

## 5. 输入、预处理与任务规则

### 5.1 截图与图片输入

- 截图支持鼠标框选、重新框选和取消。
- 首版必须在目标设备实际 DPI 缩放下验证截图坐标与图像清晰度。
- 多显示器、跨屏框选和 HDR 场景未实测前标记为“未验证”，不得默认承诺。
- 图片是否合法以实际解码结果为准，不仅依据扩展名。
- JPG/JPEG 按 EXIF 方向规范化；透明图片转换为首版固定的 RGB 输入，背景处理方式记录在技术说明中。
- 支持 Unicode 文件路径；原文件只读或原目录不可写时，不得影响应用保存自身副本。
- 输入图片尺寸、文件大小、解码后像素数和显存限制由 G1 冻结。
- 超过输入限制时默认在识别前拒绝，并显示具体超限项与当前限制值；用户可选择按明确策略缩放后继续，缩放必须记录并在界面提示可能影响识别质量（默认拒绝、可选缩放的策略为拟定规则，随 O04 在 G1 冻结）。
- 文件损坏、空白或无法解码时保留可用输入，允许重新选择或截图。

### 5.2 输出长度限制

输出长度无法在识别前检查，因此分三阶段处理：

1. **识别前**：检查输入尺寸、文件大小、像素数和可用资源。
2. **生成中**：使用模型最大生成长度或 token 上限进行约束。
3. **生成后**：检查源码长度、完整性和可处理性。

达到生成长度上限时，不将截断结果标记为识别成功；保留当前输入并提示重试、缩小区域或人工录入。具体上限随模型版本在 G1 记录。

### 5.3 画板输入规范

首版需固定并记录：

- 逻辑画布尺寸和提交图像像素尺寸。
- 窗口缩放、DPI 与画布坐标转换方式。
- 笔迹颜色、背景、画笔粗细及橡皮擦行为。
- 撤销以一次连续鼠标笔画或一次橡皮操作为单位。
- 清空需要清除全部笔迹和撤销栈。
- 空白判定基于有效笔迹，不以鼠标点击画板作为有效输入。
- 不同窗口尺寸下，同一笔迹应按统一归一化规则生成识别输入。

### 5.4 任务状态机

| 状态 | 允许操作 | 状态迁移要求 |
| --- | --- | --- |
| 输入编辑 | 修改输入、提交、切换输入、查看历史 | 提交有效输入后进入识别中 |
| 识别中 | 取消；查看处理中状态 | 输入区锁定，禁止重复创建任务 |
| 取消中 | 等待取消完成 | 新任务按钮保持不可用；取消完成并释放资源后返回输入编辑，迟到结果按 taskId 丢弃 |
| 识别成功 | 编辑、预览、复制、保存、开始新输入 | 建立或更新对应历史记录 |
| 识别失败 | 修改输入、重试、取消 | 保留当前输入，不建立成功记录 |
| 渲染失败 | 编辑、撤销、复制原文、重试预览 | 不影响源码保留；重试预览成功后返回识别成功 |
| 保存失败 | 重试保存、继续编辑、复制、返回处理未保存内容 | 不显示“已保存”；重试保存成功后返回识别成功 |

补充规则：

- 每次提交生成唯一 taskId，界面只接受与当前任务匹配的结果。
- 同一时刻最多执行一个推理任务。
- 重复点击提交不得创建新任务。
- 取消包括逻辑取消和实际资源释放；底层推理无法立即停止时，界面进入“取消中”，待任务退出或引擎确认可复用后才允许新任务。
- 取消后的迟到结果按 taskId 丢弃，不覆盖当前编辑内容。
- 首次识别成功前重试属于同一输入流程；首次成功后建立一条历史记录。
- 开始新的截图、导入或手写输入，在识别成功后建立新记录。
- 识别期间关闭应用时提示用户取消并退出；异常终止不将半成品恢复为成功记录。
- 每次识别成功均建立新历史记录；同一图片重复导入识别产生独立记录，不去重、不合并（拟定规则，G0 确认）。

## 6. LaTeX、编辑、预览与 WPS 输出契约

### 6.1 标准源码契约

首版统一使用以下规则：

- 标准输出为公式主体 LaTeX 源码。
- 不附加 Markdown 代码围栏。
- 不附加 `$...$`、`$$...$$`、`\(...\)` 或 `\[...\]` 等定界符。
- 保留公式所需的命令和环境，不将源码转换为截图或富文本后冒充 LaTeX。
- 应用内部使用 Unicode 文本；Windows 剪贴板写入 Unicode 纯文本。
- 复制、编辑和预览使用同一份当前源码，不复制过期识别版本。
- 仅清理首尾无意义空行，不擅自重排可能改变数学结构的命令。
- 原始识别版本和用户当前编辑版本分别保存。

### 6.2 首版语法子集

G1 必须冻结《首版 LaTeX 命令及 WPS 兼容表》，至少覆盖：

- 变量、数字、基本运算和关系符号。
- 上下标。
- `\frac`、`\sqrt`。
- `\sum`、`\prod` 及其上下限。
- 代表性样例涉及的 `\eta`、`\theta`、`\mid`、`\approx`、`\cdot`。
- `\text`、`\operatorname` 等内部文字标签。
- 代表性样例需要的括号、嵌套下标及范围表达。

该表需逐项标明：

- 本地预览是否支持。
- WPS 文字是否支持。
- WPS 演示是否支持。
- 是否需要等价转换。
- 不支持时的用户提示。

模型可能输出子集外语法时，应保留原文并提示“当前语法未在首版兼容范围内”，不得静默替换数学内容。

### 6.3 编辑与渲染

- 公式预览仅用于排版检查，数学内容以原图为准。
- 编辑后触发预览更新：源码变更停止 1 秒（拟定值，与 7.2 自动保存防抖口径一致，G1 冻结）后自动刷新预览；预览渲染期间允许继续编辑，仅接受与当前源码版本匹配的渲染结果，迟到结果丢弃。预览失败时保留当前输入。
- 错误提示应尽可能包含位置和原因，但不承诺检测所有 LaTeX 或数学错误。
- 撤销恢复当前会话内之前的编辑内容。
- 渲染失败状态持续可见，不得因复制成功而自动消失。
- 源码非空时允许复制；渲染失败时复制需提示“当前源码未通过预览，仍将按原文复制”。
- 渲染组件默认禁止网络、外部文件读取和 shell 命令执行。
- 如使用独立渲染进程，必须设置超时和资源上限；恶意或超长输入不得导致主界面无限阻塞。

### 6.4 WPS 使用规则

G1 需记录用户实际的：

- WPS 文字和 WPS 演示版本。
- 公式入口及 LaTeX 输入步骤。
- 所需分隔符或转换方式。
- 支持的命令和限制。

复制按钮只负责写入约定源码，不保证在 WPS 普通正文位置直接变成公式。运行说明必须提供完整操作路径。

首版验收要求 WPS 文字和 WPS 演示分别通过。如实际环境只能支持其中一个，必须由用户确认缩减范围后才能修改发布标准。

WPS 用例至少覆盖：求和、连乘、上下标、分式、根式、内部文字标签，以及粘贴、显示、再次编辑、保存和重新打开文档。

## 7. 历史记录与本地数据

### 7.1 记录内容

每条历史记录至少包含：

| 字段 | 规则 |
| --- | --- |
| 记录 ID | 本地唯一，不复用任务 ID 代替持久化设计 |
| 创建时间、更新时间 | 使用统一时间格式，界面显示本地时间 |
| 输入方式 | 截图、图片导入或鼠标手写 |
| 输入图像 | 保存实际提交识别时的图像副本 |
| 上传原件 | 图片导入时保存用户选择文件的原始副本；截图和手写不虚构上传原件 |
| 原始识别源码 | 识别成功后保存，不随用户编辑覆盖 |
| 最新编辑源码 | 保存最后一次成功写入的用户版本 |
| 模型及版本 | 包含模型版本和必要推理参数 |
| 记录状态 | 正常、保存失败或读取异常等 |

截图保存最终选区图；手写保存提交时的画布 PNG；图片导入同时保存原文件副本和实际提交图，避免后续预处理变化导致无法追溯。

### 7.2 自动保存与一致性

- 识别成功后自动建立记录。
- 用户停止编辑 1 秒后触发自动保存（1 秒为拟定值，G1 冻结；“停止编辑”指最后一次源码内容变更），并在离开编辑内容、切换记录和正常退出前再次保存。
- 保存采用临时文件写入、校验后替换等原子化方式，避免中断产生半条记录。
- 保存失败时保留内存中的修改，显示“未保存”并提供重试。
- 存在未保存修改时退出，必须提供“返回编辑并重试”和“仍要退出”的明确选择；后者需提示可能丢失本次未保存内容。
- 崩溃恢复只保证最后一次成功写入的状态，不承诺恢复所有未落盘编辑。
- 跨会话继续编辑从最近保存版本开始，不恢复上一会话撤销栈。

### 7.3 删除、损坏与容量

- 单条删除需要用户确认。
- 删除范围包括该记录独占的源码、图片副本和元数据。
- 文件删除失败时不得显示删除成功；保留可重试入口。
- 单条记录损坏时隔离并提示，其他记录仍可读取。
- 首版不自动删除旧记录，不承诺循环清理。
- 首版仅提供单条删除，不提供批量删除或清空全部历史入口（拟定规则，G0 确认）；磁盘空间管理依赖占用显示和逐条删除。
- 设置或历史页面显示历史数据目录、总占用空间和磁盘剩余空间，提供手动删除入口。
- 保存前检查空间；空间不足时识别、编辑和复制仍可使用，但不得宣称历史已保存。

### 7.4 本地数据与隐私

首版遵循以下规则：

- 除用户主动触发的模型下载或修复外，不发送用户图片、笔迹、源码或历史内容。
- 首版不加入默认开启的统计上报、自动云同步和后台更新检查。
- 日志不得记录公式源码、图片内容、笔迹内容、完整用户文件路径或历史正文。
- 日志仅保留诊断所需的状态、错误码、模型版本和耗时，并采用大小或数量轮转。
- 崩溃转储默认不包含用户内容；如需改变，必须另行评审。
- 卸载不得静默删除用户历史；卸载说明需明确数据保留位置及手动删除方式。
- 离线验收需检查不存在未声明的网络请求。
- 实际目录在实现后写入运行说明，统一放在当前用户的应用数据目录，不要求写入原始图片所在目录。

| 场景 | 用户可见行为与恢复路径 |
| --- | --- |

## 9. 非功能、安装与安全要求

### 9.1 性能与资源

- 计时起点为用户点击提交，终点为当前任务源码和首次预览均显示。
- 图像处理、推理、结果整理和首次渲染均计入识别耗时。
- 应用冷启动、模型首次加载和模型下载单独统计，不混入模型就绪后的识别耗时。
- 印刷和手写分别报告中位数、P95、失败数及超时数。
- 超时和失败样例不得从性能统计中静默剔除。
- 渲染失败的样例以渲染失败提示显示为计时终点，纳入性能统计并单独标注；该样例计入“识别完成”，不计入“本地可渲染”。
- 测试记录输入尺寸、样例复杂度、模型预热状态、推理参数、显卡、显存、内存、Windows、驱动和运行环境。
- 另执行 30 次连续任务稳定性测试，不得用该测试替代正式性能样例统计。

稳定性通过条件：

- 无崩溃、死锁和无法退出的处理中状态。
- 所有任务均有明确终态。
- 结果与任务、原图和历史记录一一对应。
- 取消和重试后无旧结果覆盖。
- 测试结束后仍能继续识别。
- 内存和显存无持续不可释放增长；具体判定阈值在 G1 记录。

### 9.2 安装与首次运行

首次运行顺序：

1. 检查 Windows、显卡、驱动和基础运行环境。
2. 展示模型大小、存放位置和预计空间需求。
3. 检查可用空间。
4. 经用户确认后下载模型。
5. 校验文件完整性和可信校验值。
6. 加载模型并运行本地样例。
7. 准备完成后进入使用流程。

其他要求：

- 环境明显不满足时，不得先下载大模型再告知无法运行。
- 校验值必须与模型版本绑定，并来自可信发布配置。
- 安装或准备失败不得破坏已有可用版本。
- 临时下载文件、重试和清理行为需在运行说明中记录。
- 公式渲染资源、字体及运行组件随本地交付准备。
- 后续启动在模型完整且环境未变化时直接进入使用流程。
- 模型、权重、推理依赖、渲染库和字体的来源、版本、许可证及再分发条件为 G3 发布门禁。

### 9.3 本地渲染安全

渲染组件需通过以下测试：

- 禁止 shell escape 或等价外部命令能力。
- 不允许通过公式源码读取本地文件或加载远程资源。
- 超长源码、深层嵌套和恶意命令不会无限阻塞界面。
- 渲染超时后可恢复编辑。
- 渲染错误不向用户暴露无关的本地敏感路径。

## 10. 验收方案

### 10.1 验收集管理

- 印刷与手写分别建立调试集、调参集和最终验收集。
- 最终验收集在模型调试前冻结，保存清单、文件哈希、输入条件和人工标准答案。
- 调试样例不得并入最终验收集后仍宣称独立验收。
- 验收集不得通过删除失败样例或替换困难样例提高通过率。
- 如必须调整验收集，需重新确认版本并完整重测。
- 验收报告记录样本数量和局限，不将固定小样本结果表述为对任意公式的泛化保证。

### 10.2 印刷公式质量

最终验收集不少于 30 张，覆盖：

- 简单公式。
- 复杂公式。
- 求和、连乘、上下限。
- 希腊字母。
- 条件概率。
- 嵌套下标。
- 内部文字标签。
- 用户提供的代表性多行公式。

“清晰印刷公式”至少满足：主要笔画连续，在原始或合理缩放视图下可由人工无歧义转录；模糊、截断、低分辨率等异常图不计入清晰集，单独进入异常测试。

每个样例分别记录：

| 指标 | 判定 |
| --- | --- |
| 识别完成 | 未失败、未超时、未发生输出截断 |
| 首识数学正确 | 未经人工编辑，符号和数学结构与原图一致 |
| 本地可渲染 | 当前首识源码可通过首版预览 |
| WPS 可直接使用 | 按约定步骤可粘贴、显示、修改和保存 |
| 端到端直接可用 | 以上条件全部满足，且无需人工修改数学源码 |

允许多种等价 LaTeX 写法，以数学结构为准。标准答案先人工转录，存在分歧时双人复核；仍无法一致的，由用户或指定复核人仲裁。

主要质量门槛：30 张中至少 27 张端到端直接可用。首识数学正确率、可渲染率和 WPS 可用率同时分别报告，不得相互替代。

### 10.3 公式主体处理

F05 使用至少 10 组独立对照样例，每组包含干净公式图和带编号或解释文字的版本。

通过要求：

- 不得误删公式内部的函数名、文字下标、数字、上下限和符号关系。
- 原图连乘下标等细节必须忠实保留。
- 外围内容归属不明时，优先保留内容并提示重新框选或人工校对，不得静默猜测删除。
- 任一样例发生数学内容误删，F05 不通过。
- 外围编号和解释文字的清除结果单独记录；相关错误同时影响端到端直接可用率。

### 10.4 代表性公式

代表性公式的人工参考转录保留如下，最终仍须结合原图核对：

```latex
p_{\text{RAG-Sequence}}(y\mid x)
\approx
\sum_{z\in\operatorname{top-k}(p(\cdot\mid x))}
p_{\eta}(z\mid x)\,p_{\theta}(y\mid x,z)
=
\sum_{z\in\operatorname{top-k}(p(\cdot\mid x))}
p_{\eta}(z\mid x)
\prod_i^N p_{\theta}(y_i\mid x,z,y_{1:i-1})
```

重点检查：

- `RAG-Sequence`。
- `top-k`。
- 条件概率竖线。
- `\eta` 与 `\theta`。
- 求和下标。
- `y_{1:i-1}`。
- `\prod_i^N`，原图连乘下标为 `i`。

### 10.5 鼠标手写质量

- 最终验收集建议不少于 20 个真实鼠标书写样例。
- 六类基础结构每类至少 2 个，其余用于简单组合和易混淆情况。
- 记录书写者、画布参数、是否参与过调试及标准答案。
- 首识正确在人工编辑前统计。
- 建议目标：至少 16/20 首识数学正确，即 80%，待用户确认。
- 字母、数字、上下标混淆分别统计。

“失败后可通过纠错流程完成使用”不作为首识正确率的放宽条件，单独记录：

- 修复成功率。
- 修复耗时。
- 编辑次数。
- 是否需要完全重写。

修复指标首版只报告，不设置无限制手工修改即可通过的验收口径。

### 10.6 性能验收

建议将“约 5 秒”定义为：

在目标设备、模型就绪、固定首版验收集和冻结输入限制下，印刷与手写分别统计，模型就绪后的单任务识别及首次预览 P95 不超过 5 秒。

该口径及最终阈值需用户结合实测确认。样本量不足时不将 P95 表述为广泛设备保证，同时列出每张样例耗时。

冷启动、模型加载和下载耗时单独展示，不纳入上述 5 秒口径。

### 10.7 WPS、离线与安装验收

**WPS：**

- 分别记录 WPS 文字和演示版本。
- 按统一操作步骤测试全部代表性结构。
- 验证粘贴、显示、修改、保存和重新打开。
- 记录不支持语法及必要的人工步骤。

**离线：**

完成模型准备后断网并重启，依次验证：

- 截图。
- 图片导入。
- 鼠标手写。
- 本地识别。
- 预览。
- 历史读取和继续编辑。
- 复制。
- 无未声明网络请求。

**安装：**

在干净用户环境复现安装、环境检查、模型下载、校验、首次加载、离线重启及异常恢复。

### 10.8 边界与异常用例

至少覆盖：

- 空白选区、空白画板、空白图片。
- 图片损坏、伪扩展名、透明图、EXIF 旋转和 Unicode 路径。
- 图片过大、像素过多、显存不足和磁盘不足。
- 重复提交、取消后立即重试、取消后迟到结果。
- 识别中关闭应用。
- 输出截断、识别失败、超时。
- 括号缺失、非法命令、超长源码和渲染超时。
- 剪贴板占用或写入失败。
- 自动保存失败、异常退出和继续退出。
- 历史单条损坏、删除失败及存储空间不足。
- 模型下载中断、文件损坏、校验失败和下载源不可用。

| 运行说明 | 是 | 包含联网准备、离线运行、目录和 WPS 步骤 |
| 码道使用证明 | 是 | 按赛事要求整理 |
| 介绍材料 | 是 | 8～10 页 |
| 演示视频 | 是 | 建议 3 分钟以内 |
| 验收报告 | 建议纳入 | 包含样例版本、环境和未达标项 |
| 普通用户安装包 | 打包前确认 | 根据实际体积和赛事规则决定 |
| 模型权重 | 默认不直接打包 | 如改为随包分发，需同时检查体积和许可证 |

G3 前必须确认：

- 评审环境是否允许首次联网下载模型。
- 是否接受安装包或模型的外部下载方式。
- 若要求完全离线复现，当前“模型首次下载”交付方式是否满足赛事要求。

未确认前不得默认可通过外部链接补交关键运行文件。

主要风险：

- **技术风险**：印刷、手写和 5 秒目标可能无法由同一模型同时满足。
- **兼容风险**：本地预览可用不代表 WPS 可直接使用。
- **交付风险**：模型下载、安装包体积和 ZIP 限制可能冲突。
- **进度风险**：验证、安装、验收和赛事材料集中在五天内。
- **数据风险**：历史图片持续增长、保存失败和异常退出可能造成空间或一致性问题。
- **合规风险**：模型权重、字体及依赖的再分发条件可能影响最终选型。
