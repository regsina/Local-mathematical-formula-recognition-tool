## 1. 评估总览

**风险等级：高。** 当前文档可用于启动技术验证，但核心 LaTeX/WPS 输出契约、印刷公式范围与主体提取判定、正式验收基线尚未冻结，且赛事交付缺少倒排计划，直接开展全功能开发存在选型返工、验收争议和逾期风险。

## 2. 阻断性问题（必须改）

### B01｜核心输出及 WPS 使用契约未定义，编辑、预览、复制无法形成统一实现

- **位置**：`编辑与复制规则`、F06～F08、`WPS 与离线验证`
- **问题描述**：LaTeX 支持子集、源码规范化规则、复制格式、WPS 粘贴入口及分隔符均待验证；尚未明确是否输出 Markdown 代码围栏、公式定界符、换行，以及预览渲染与 WPS 渲染之间的语法差异。WPS 文字和 WPS 演示也未明确是两者都必须通过，还是任一通过即可。
- **原因及影响**：F06 的渲染器选型、F07 的语法纠错、F08 的剪贴板实现和测试预期均依赖该契约；若后期才发现预览支持但 WPS 不支持，可能反向修改模型后处理、编辑器及验收样例。
- **修改建议**：在技术验证结束、完整功能开发前冻结一张“输出契约表”，至少明确：
  1. 标准输出的编码、换行、空白、定界符及代码围栏处理；
  2. 首版保证支持的命令和环境，以及不支持语法的处理；
  3. 剪贴板写入类型及完整 WPS 操作步骤；
  4. WPS 文字、演示各自的目标版本和通过条件；
  5. 渲染失败时复制按钮是否可用，以及复制内容的准确含义。
- **涉及视角**：产品、研发、测试、设计

### B02｜“单个公式”和“公式主体提取”的可执行边界不清

- **位置**：`产品目标与使用条件`、F05、`代表性公式与判定标准`、`印刷公式质量`
- **问题描述**：代表性公式包含多行、约等号和等号，但文档未明确多行公式是否均属于“单个公式”，也未列出矩阵、分段函数、对齐环境、多公式混排等是否在首版范围内。F05 仅描述清除外围编号和解释文字，没有规定归属不明时哪些内容允许删除、哪些必须保留，以及独立样例的通过标准。
- **原因及影响**：模型选型、图像裁剪、后处理和测试标注会采用不同边界；尤其“清除文字”和“保留内部文字标签”存在相邻区域误判风险，可能出现数学内容被静默删改。
- **修改建议**：
  1. 增加印刷公式支持/不支持清单，明确多行、多公式、矩阵、分段函数、对齐环境等范围；
  2. 为编号、解释文字、内部文字下标、函数名分别提供正反例和标准答案；
  3. 明确归属不明时不得静默猜测的产品行为，例如保留内容并提示重新框选；
  4. 为 F05 单独规定样例数量、数学内容保留要求及通过门槛，不能只以“可重新框选”替代识别结果判定。
- **涉及视角**：产品、研发、测试

### B03｜正式验收基线尚未锁定，也没有冻结节点和未达标后的范围决策

- **位置**：`鼠标手写质量`、`性能与资源`、`技术方向与待验证项`、`本次审阅需要确认的补充`
- **问题描述**：手写 80% 仍为草稿；约 5 秒的统计口径、识别超时、图片及输出上限均待实测。文档允许根据验证结果调整目标，但没有规定由谁、在哪个里程碑前确认，以及模型无法同时满足印刷、手写、速度要求时如何缩减范围。
- **原因及影响**：技术验证可以开始，但最终验收集、测试通过条件和首版功能承诺无法基线化；验证后期再调整范围，容易使已经完成的手写、安装或界面工作返工。
- **修改建议**：增加“验收基线冻结”里程碑和开放项清单，为每项指定负责人、输入证据、确认人及截止节点；冻结内容至少包括印刷/手写正确率、性能口径、超时和资源上限、WPS 范围。另需预先约定未达标决策顺序，例如降低样例范围、调整性能目标或暂缓手写，不得直接修改测试样例使原目标通过。
- **涉及视角**：产品、研发、测试

## 3. 高风险问题（建议改）

### H01｜识别任务状态机不完整，取消规则可能与“单任务”规则冲突

- **位置**：`输入与任务规则的建议默认值`、`异常与恢复`
- **问题描述**：文档允许取消后丢弃迟到结果，但未说明取消是否真正停止推理、何时允许提交下一任务。若旧任务仍在运行而用户立即发起新任务，可能实际并发执行，与“同一时刻执行一个识别任务”冲突。识别中切换输入、关闭窗口、重新截图、重试及历史记录归属也未定义。
- **原因及影响**：容易出现结果串任务、显存重复占用、旧结果覆盖新编辑内容或重复生成历史记录。
- **修改建议**：补充状态机和按钮可用性矩阵，覆盖空闲、输入就绪、识别中、取消中、成功、失败、渲染失败、保存失败等状态；明确任务 ID 生命周期、实际取消与逻辑取消的区别、资源释放时点，以及重试和再次识别是新建记录还是更新原记录。
- **涉及视角**：产品、研发、测试、设计

### H02｜输入限制存在不可执行表述，截图和图片边界条件不足

- **位置**：F01、F02、`输入与任务规则的建议默认值`
- **问题描述**：“输出长度上限……在处理前检查”无法执行，因为识别前不知道输出长度。图片超限时拒绝、缩放还是压缩也未明确；截图未覆盖多显示器、DPI 缩放、窗口最小化及跨屏框选，图片未说明 EXIF 方向、透明通道、伪扩展名、中文路径和只读目录等处理。
- **原因及影响**：研发会各自理解预处理策略，测试无法根据“超出资源限制时说明处理方式”构造确定预期；高 DPI 截图还可能直接影响识别正确率。
- **修改建议**：将限制拆成“输入前检查、生成中限制、输出后校验”三阶段；输出达到 token/字符上限时明确终止、提示及是否保留部分结果。补充首版支持和不支持的截图环境、图片解码规范化及超限处理表，不要求首版支持所有格式，但必须有确定行为。
- **涉及视角**：研发、测试、设计

### H03｜鼠标画板缺少影响识别一致性的输入规范

- **位置**：F03、`鼠标手写输入`、`鼠标手写质量`
- **问题描述**：画布像素尺寸、窗口缩放和 DPI 处理、笔迹粗细、橡皮擦粒度、撤销粒度、空白判定及提交图像归一化均未定义；“简单组合”也没有嵌套深度或结构边界。手写验收集未像印刷验收集一样要求与调试样例分离。
- **原因及影响**：同一笔迹在不同窗口或缩放下可能生成不同识别输入，20 张样例的结果难以复现；调试样例与验收样例混用会使首识正确率失真。
- **修改建议**：规定提交时固定格式的画布图像及坐标映射，明确画笔、橡皮擦、撤销和空白判定行为；用正反例界定简单组合。手写样例按六类结构给出数量分布，并执行调试集、调参集、最终验收集隔离。
- **涉及视角**：产品、研发、测试、设计

### H04｜历史记录的数据一致性和异常退出规则不足

- **位置**：F09、`历史记录规则的建议默认值`、`异常与恢复`
- **问题描述**：自动保存只描述离开编辑内容或正常退出前写入，未明确编辑中的保存频率及崩溃时允许丢失多少内容；保存失败后用户继续退出、单条记录损坏、存储持续增长、删除是否同时删除图片副本等没有规则。“原始图片”也未区分上传原件、框选裁剪图和主体提取图。
- **原因及影响**：可能出现源码与原图错配、异常记录阻塞整个历史列表、退出丢稿或磁盘被历史图片持续占用。
- **修改建议**：补充记录 ID、创建/更新时间、原图类型、任务状态和模型版本等数据字典；定义原子写入、自动保存触发点、异常退出恢复、保存失败时退出确认、单条损坏隔离、删除Scope及容量清理策略。若首版不设容量上限，也应明确风险由用户清理还是提供数量/空间限制。
- **涉及视角**：产品、研发、测试

### H05｜正确率判定仍存在主观空间，手写“纠错后可用”不能作为通过条件

- **位置**：`质量目标`、`印刷公式质量`、`鼠标手写质量`
- **问题描述**：印刷样例需同时满足识别完成、可渲染、数学结构一致和 WPS 可用，但未明确任一失败是否均计入识别失败，也未规定人工判断数学等价的复核与分歧处理。“清晰”的输入条件没有可操作定义。手写失败样例“能够经过源码纠错流程完成使用”没有编辑时间或操作限制，即使完全识别错误也可通过手工重写满足。
- **原因及影响**：不同测试人员可能得到不同正确率；30 张和 20 张样例的结果只能代表固定验收集，不能支撑未限定范围的泛化结论。
- **修改建议**：制定逐样例评分表，分别记录识别成功、数学正确、可渲染、WPS 可用，并明确总通过公式；定义清晰度/输入采集条件和争议复核方式。将“纠错后可用”改为单独记录的修复成功率、编辑时长或编辑次数，不并入手写首识正确率；报告实际通过数量及样本局限。
- **涉及视角**：产品、测试、研发

### H06｜性能测试有记录项，但缺少可判定门槛

- **位置**：`速度期望`、`性能与资源`
- **问题描述**：约 5 秒未明确适用于中位数、P95 还是每张样例；30 次连续识别既用于稳定性又被用于记录 P95，但未说明样本组合、模型预热、输入分辨率、超时是否计入，以及内存释放和界面响应的通过阈值。
- **原因及影响**：测试报告可能数据齐全但仍无法判定是否通过，30 个混合样例直接计算 P95 也容易受样例顺序和复杂度影响。
- **修改建议**：将“体验性能验收”和“30 次稳定性测试”分开；固定计时起止点、模型就绪条件、样例分组及统计方法，明确超时和渲染失败如何计入。稳定性另设崩溃、任务错配、显存/内存持续增长和界面可操作的判定条件。
- **涉及视角**：研发、测试

### H07｜安装、模型下载及修复流程尚不能完整验收

- **位置**：F10、`异常与恢复`、`安装与参赛交付`
- **问题描述**：未明确下载前磁盘空间检查、下载服务不可用、代理/防火墙、重启后续传、安装或模型准备失败后的回滚；“完整性检查”未规定可信校验值来源。不支持显卡环境只要求提供修复说明，未明确是否阻止大模型下载及如何安全退出。许可证和校验信息虽要求选定后记录，但未设为交付门禁。
- **原因及影响**：干净环境安装是独立交付流程，异常时可能留下不可用的大文件或重复下载；模型、权重和依赖许可证若临近打包才检查，可能要求更换技术方案。
- **修改建议**：绘制首次运行流程及失败回滚路径，明确环境检查先于模型下载、空间预检、可信来源与哈希/签名校验、重试和清理规则；将模型、权重、推理依赖、渲染字体等许可证核查列为安装包发布前置条件。
- **涉及视角**：研发、测试、安全合规

### H08｜“本地处理”尚未转化为可核查的数据与隐私规则

- **位置**：`产品目标与使用条件`、`WPS 与离线验证`、历史记录及异常恢复相关章节
- **问题描述**：仅要求核查处理、日志和存储路径，未列明应用数据目录、访问权限、日志是否包含图片路径或 LaTeX、崩溃转储、缓存清理、删除记录及卸载后的数据保留策略，也未明确除模型下载外是否存在更新检查或其他网络请求。
- **原因及影响**：无法通过测试证明用户内容没有进入日志或意外网络请求；删除记录后仍可能残留图片副本。
- **修改建议**：增加本地数据清单和生命周期表，逐项规定内容、路径、保留时间、删除行为及是否进入日志；默认禁止在日志和崩溃信息中记录公式源码、笔迹及图片内容，并将断网后的网络行为检查写入验收用例。
- **涉及视角**：产品、研发、测试、安全合规

### H09｜用户可编辑 LaTeX 的渲染安全约束缺失

- **位置**：F06、F07、`编辑与复制规则`、`技术方向与待验证项`
- **问题描述**：渲染库尚未选择，文档未限制渲染器访问网络、本地文件或外部命令，也未规定渲染超时和资源限制。
- **原因及影响**：若选用完整 TeX 引擎或支持外部资源的组件，不可信源码可能带来文件访问、命令执行或渲染卡死风险；即使采用受限渲染器，也需要防止超长或复杂输入阻塞界面。
- **修改建议**：优先采用禁用外部资源和命令执行的受限渲染配置；若必须使用完整 TeX 引擎，应隔离进程、禁用 shell escape 和外部访问，并设置超时及资源上限。将恶意命令、外部图片、超长嵌套源码纳入安全异常测试。
- **涉及视角**：研发、测试、安全

### H10｜赛事倒排与交付物边界不足，当前范围缺少可执行的降级顺序

- **位置**：`安装与参赛交付`、三阶段开发表、`本次审阅需要确认的补充`
- **问题描述**：文档日期为 2026 年 11 月 23 日，初赛截止日期为 11 月 28 日，但三个阶段没有工期、负责人和里程碑；F01～F10 均属当前版本，技术验证不通过时没有已确认的交付降级方案。普通用户安装包“另行构建”，但是否进入 500MB ZIP、评审环境是否允许联网下载模型也未明确。
- **原因及影响**：模型选型、离线安装、手写验收和比赛材料存在串行依赖，任一延误都会压缩打包与视频时间；最终可能出现 ZIP 合规但应用无法复现，或安装包、模型超出提交约束。
- **修改建议**：按截止日期倒排“方案冻结、功能冻结、安装包复现、验收完成、材料打包”节点，明确最小可交付范围和砍 scope 顺序；增加交付物清单，逐项标注是否进入 ZIP、预计体积、是否需联网及负责人，并至少进行一次干净环境打包演练。
- **涉及视角**：产品、研发、测试、项目管理

## 4. 优化建议

### O01｜需求价值缺少效率基线

- **位置**：`需求目标与价值`、产品目标表
- **问题描述**：以减少手工输入时间为价值，但只有识别率和速度指标，没有手工录入基线或任务完成效率指标。
- **修改建议**：补充代表性公式的手工输入耗时、识别后修正耗时及端到端任务完成率；首版不采集线上数据时，可通过验收样例和本地可用性测试测量。
- **涉及视角**：产品、测试

### O02｜需求、验证和开放项之间缺少追踪关系

- **位置**：F01～F10、各验收章节、`本次审阅需要确认的补充`
- **问题描述**：功能编号没有与验收集、异常用例和交付阶段建立对应，“建议默认值”“待实测”“待用户确认”分散在正文中。
- **修改建议**：增加追踪矩阵和开放项表，列明需求 ID、验收用例、当前状态、负责人及冻结版本；用户确认后将“建议默认值”改为正式规则或明确移出首版。
- **涉及视角**：产品、研发、测试

### O03｜界面设计仅有局部参考，主流程状态反馈不足以直接出设计稿

- **位置**：F06～F09、画板交互参考、异常与恢复表
- **问题描述**：未说明原图、源码、预览在窗口缩放及长公式下的布局，也缺少识别中、保存失败、历史图片缺失等统一状态设计。
- **修改建议**：补充主界面和关键状态原型，至少覆盖长源码换行/滚动、大图片缩放、错误提示位置、按钮禁用及复制反馈；撤销、清空、删除等操作明确快捷键和防误触要求。
- **涉及视角**：设计、产品、测试

### O04｜本地图片链接影响 PRD 独立流转

- **位置**：`代表性公式与判定标准`
- **问题描述**：复杂公式原图和画板参考图使用相对路径，文档未说明资源清單及打包方式，单独转发正文时无法核对关键依据。
